# Fork 维护规范

## 分支约定

- `upstream/beta`：原作者测试分支，只读取和合并。
- `dx`：自己的开发与上游整合分支。
- `main`：自己的发布分支，UPM 私服从该分支同步。

## 递增版本号

版本规则：

1. `upstream/beta` 的版本号升级后，使用“上游 patch + 1”并从 `beta.1` 开始。
2. 上游版本号未变时，无论是合并上游新提交还是自己继续修改，下次发布都只递增 beta 序号。
3. 包内版本不带 `v`；Git tag 带 `v`。

示例：

```text
upstream/beta = 2.1.3  -> 2.1.4-beta.1
自己继续修改             -> 2.1.4-beta.2
upstream/beta = 2.1.5  -> 2.1.6-beta.1
自己继续修改             -> 2.1.6-beta.2
```

执行以下 PowerShell 命令直接计算下一版：

```powershell
git fetch origin --prune
git fetch upstream --prune

$upstreamVersion = (git show upstream/beta:SkillsForUnity/package.json | ConvertFrom-Json).version
if ($upstreamVersion -notmatch '^(?<major>\d+)\.(?<minor>\d+)\.(?<patch>\d+)') {
  throw "无法解析上游版本：$upstreamVersion"
}
$upstreamBase = [version]"$($Matches.major).$($Matches.minor).$($Matches.patch)"

$latestForkBeta = git ls-remote --tags --refs origin "refs/tags/v*-beta.*" |
  ForEach-Object {
    if ($_ -match 'refs/tags/v(?<base>\d+\.\d+\.\d+)-beta\.(?<beta>\d+)$') {
      [pscustomobject]@{ Base = [version]$Matches.base; Beta = [int]$Matches.beta }
    }
  } |
  Sort-Object @{ Expression = 'Base'; Descending = $true }, @{ Expression = 'Beta'; Descending = $true } |
  Select-Object -First 1

if ($latestForkBeta -and $latestForkBeta.Base -gt $upstreamBase) {
  $nextVersion = "$($latestForkBeta.Base)-beta.$($latestForkBeta.Beta + 1)"
} else {
  $nextVersion = "$($upstreamBase.Major).$($upstreamBase.Minor).$($upstreamBase.Build + 1)-beta.1"
}

"upstream/beta: $upstreamVersion"
"next version: $nextVersion"
```

当前 `upstream/beta` 为 `2.1.3`，且 Fork 还没有 beta tag，所以该命令输出 `next version: 2.1.4-beta.1`。

## 发布流程

### 1. 合并上游

```powershell
git switch dx
git status --short --branch
git fetch upstream --prune
git log --oneline dx..upstream/beta
git merge upstream/beta
```

### 2. 修改版本

将新版本（如 `2.1.4-beta.1`）同步到：

- `SkillsForUnity/Editor/Skills/SkillsLogger.cs`
- `SkillsForUnity/package.json`
- `SkillsForUnity/unity-skills~/scripts/unity_skills.py`
- `agent.md`
- `README.md`
- `README_CN.md`
- `CHANGELOG.md`

检查是否遗漏：

```powershell
rg -n "2\.1\.4-beta\.1" agent.md README.md README_CN.md CHANGELOG.md SkillsForUnity/package.json SkillsForUnity/Editor/Skills/SkillsLogger.cs SkillsForUnity/unity-skills~/scripts/unity_skills.py
git diff --check
```

### 3. 提交并发布

```powershell
git switch dx
git add <本次变更文件>
git commit -m "chore: bump version to 2.1.4-beta.1"
git push origin dx

git switch main
git pull --ff-only origin main
git merge --ff-only dx
git push origin main

git tag -a v2.1.4-beta.1 -m "v2.1.4-beta.1"
git push origin v2.1.4-beta.1
```

tag 只在实际发布时创建，普通开发提交不打 tag。不要使用原作者 `.claude/commands/release.md` 中的 `reset --hard` 和强制推送流程。

## 发布到个人 npm

只有用户明确要求“上传/发布到个人 npm”时才执行。认证信息从 `.agents/config/npm.json` 读取，不得在日志或回复中输出密码。该文件必须保持在 `.gitignore` 中，不得提交。

先确认 Git tag 已发布，再在仓库根目录执行：

```powershell
$config = Get-Content -Raw .agents/config/npm.json | ConvertFrom-Json
$npm = $config.npm
$registry = $npm.registry.TrimEnd('/')
$package = Get-Content -Raw SkillsForUnity/package.json | ConvertFrom-Json
$spec = "$($package.name)@$($package.version)"
$distTag = if ($package.version -match '-(?<tag>[A-Za-z][0-9A-Za-z-]*)') {
  $Matches.tag.ToLowerInvariant()
} else {
  'latest'
}

$registryUri = [uri]$registry
$authPrefix = "//$($registryUri.Authority)$($registryUri.AbsolutePath.TrimEnd('/'))/"
$npmrc = Join-Path ([IO.Path]::GetTempPath()) "unity-skills-$PID.npmrc"
$encodedPassword = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($npm.password))

@(
  "registry=$registry/"
  'always-auth=true'
  "$authPrefix`:username=$($npm.username)"
  "$authPrefix`:_password=$encodedPassword"
  "$authPrefix`:email=$($npm.email)"
  "$authPrefix`:always-auth=true"
) | Set-Content -Encoding UTF8 $npmrc

$oldNpmrc = $env:NPM_CONFIG_USERCONFIG
$env:NPM_CONFIG_USERCONFIG = $npmrc
try {
  npm whoami --registry $registry
  if ($LASTEXITCODE -ne 0) { throw 'npm 认证失败' }

  $viewResult = npm view $spec version --registry $registry 2>&1
  if ($LASTEXITCODE -eq 0) { throw "$spec 已存在，不得重复发布" }
  if (($viewResult | Out-String) -notmatch 'E404|404 Not Found|not in this registry') {
    throw "无法确认 $spec 是否存在，停止发布"
  }

  npm publish ./SkillsForUnity --access public --tag $distTag --registry $registry
  if ($LASTEXITCODE -ne 0) { throw "$spec 发布失败" }

  npm view $spec version dist-tags --registry $registry
  if ($LASTEXITCODE -ne 0) { throw "$spec 发布后验证失败" }
} finally {
  if ($null -eq $oldNpmrc) {
    Remove-Item Env:NPM_CONFIG_USERCONFIG -ErrorAction SilentlyContinue
  } else {
    $env:NPM_CONFIG_USERCONFIG = $oldNpmrc
  }
  Remove-Item -LiteralPath $npmrc -Force -ErrorAction SilentlyContinue
}
```

`2.1.4-beta.1` 会使用 `beta` dist-tag，稳定版使用 `latest`。npm 版本发布后不能原地覆盖；如果同名版本已存在，必须先递增版本号。
